The old pretrained checkpoint in `pth/BEVDepth` was undertrained at mAP=0.2955 / NDS=0.3278 — the retrain is **+0.21 NDS**, well above the user's ~0.36 target. wandb: `Robust_Ex/BEVDepth-CARLA/runs/7bex50bw` (run `carla_sedan`). Ckpt: `outputs/carla_sedan/BEVDepth-CARLA/7bex50bw/checkpoints/epoch=23-step=6528.ckpt`.

**Config** (CBGS OFF, fair-comp regime per [[bev-fair-comparison-matrix]]): ResNet-50, BEV 128×128 (x,y∈[-51.2,51.2] cell 0.8), single-frame, 6 classes, aug OFF, eff-batch 64 (`-b 16 --gpus 2 --accumulate_grad_batches 2`), **lr 2e-4**, 24 epochs, MultiStepLR[19,23], fp32, no EMA. NDS plateaus ~0.535–0.541 from ep14; LR decays gave no big bump. suv/bus exps are identical except `VEHICLE=` (auto-swaps data pkl + `v1.0-carla_<veh>_eval` DB); user runs those themselves.

**Why / gotcha:** repeated `rc=137` training deaths on this shared box were NOT GPU OOM — they were **`/dev/shm` exhaustion**. `/dev/shm` is a 100 GB container mount kept ~2/3 full by concurrent jobs (user's BEVDet train + VP eval), leaving <35 GB. PyTorch's default `file_descriptor` tensor-sharing stages every prefetched batch through /dev/shm; with num_workers×DDP-ranks×prefetch (~16 batches in flight) it overruns and the OS SIGKILLs a dataloader worker on the first fetch ("DataLoader worker killed by signal: Killed").

**How to apply:** for ANY multi-GPU training on this box, set `torch.multiprocessing.set_sharing_strategy('file_system')` + `export TMPDIR=/tmp` (1.2 TB tmpfs, ~870 GB free) so tensors mmap to the big tmpfs instead of the crowded /dev/shm. Already committed in BEVDepth `carla_base.py`. Also: PL `ModelCheckpoint` here saves ONLY the last epoch (no `save_top_k` on val/NDS) — add monitoring if best-ckpt is needed. Commits pushed as shdragron <shdragron@hanyang.ac.kr> (NO Claude co-author) to `shdragron/BEVDepth_CARLA`.

**TF32/cuDNN divergence gotcha (commit 97eb53c):** on a fresh clone in a different env (torch 2.7.1 / **cuDNN 9.7.1**, B200), `depth_loss` diverges upward (19→47→107…) while `detection_loss` stays flat — NOT fp16 (model is all `autocast(False)`=fp32, Trainer precision=32) and NOT LR (lr=2e-4 correct). Root cause: even at precision=32, TF32 stays on for cuDNN convs (`cudnn.allow_tf32` defaults True), and **cuDNN 9.7.1 picks an unstable TF32 conv kernel for the depth net on B200**; cuDNN 9.19.0 (the working env) is stable with the same flag. Confirmed: setting `cuda.matmul.allow_tf32=False` + `cudnn.allow_tf32=False` + `set_float32_matmul_precision('highest')` holds depth_loss flat (~20 to step 119). Now baked into `carla_base.py` (full fp32, all 3 vehicles, train+eval). Lesson: README "torch 2.x" was too loose → pin validated torch 2.11.0+cu128 / cuDNN 9.19, and force fp32 in-code for cross-version reproducibility. Sedan's 0.5354 was TF32-on but on cuDNN 9.19 TF32-on≈off (negligible), so it stays comparable.

**All 3 vehicles done (2026-06-05) — best NDS: suv 0.5564 > sedan 0.5407 > bus 0.4279** (order = viewpoint ease; bus has an extreme camera rig ±5.7m fwd/back, 4.08m high per source DB `calibrated_sensor.json`, so it's the hardest). final-epoch (saved ckpt): suv 0.5474 / sedan 0.5354 / bus 0.4182. Ckpts: `outputs/carla_{suv,bus}/BEVDepth-CARLA/*/checkpoints/epoch=23-step=6528.ckpt`.

**Two training gotchas found running suv/bus (Why + How to apply):**
1. **1-GPU (BN batch 16) is NOT enough — use 2-GPU (NaiveSyncBatchNorm → BN 32).** Running suv/bus as two parallel 1-GPU jobs (`-b 16 --gpus 1 --accumulate_grad_batches 4`) gave near-zero NDS: suv 0.0076 (train loss converged to 23 but eval near-0 = bad BN *running stats* from small batch), bus 0.0000 (train loss stuck ~200). Same code on **2-GPU** (`-b 16 --gpus 2 --accumulate_grad_batches 2`, BN 32) trained fine. Verified clean: a sedan-ckpt eval on suv/bus val was ~0 too (cross-vehicle transfer fails = LSS viewpoint sensitivity), confirming data was fine and it was a training issue. → For these CARLA exps, always train 2-GPU; don't split into 1-GPU jobs.
2. **2-GPU training is marginally stable — add `--gradient_clip_val 35`.** Which vehicle diverges is stochastic (1-GPU: bus failed/suv ok; 2-GPU no-clip: suv DIVERGED loss 327→500 NDS 0 / bus ok). A gradient spike derails a run into a high-loss plateau. `--gradient_clip_val 35` (now in `_run_veh_train_2gpu.sh`) fixed suv: epoch-0 NDS 0.3182 (= sedan's 0.3166) → converged 0.556. grad-clip only caps rare spikes so results stay comparable to non-clip runs. **Minor config drift across the 3 runs** (sedan: TF32-on, no clip; bus: TF32-off, no clip; suv: TF32-off, clip 35) — differences are noise-level but if strict fairness needed, re-run all 3 with 2-GPU + clip 35 + TF32-off.
